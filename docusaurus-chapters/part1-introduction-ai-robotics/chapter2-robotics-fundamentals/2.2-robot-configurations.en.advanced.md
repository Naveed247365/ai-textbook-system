# Robot Configurations (English Advanced)

## Mathematical Modeling of Robot Configurations

### Configuration Space (C-Space)

The configuration space represents all possible positions and orientations of a robot. For a robot with n degrees of freedom, the configuration space is typically represented as:

**C = R^m × SO(3) × T^k**

Where:
- R^m: Euclidean space for prismatic joints
- SO(3): Special Orthogonal group for rotational joints
- T^k: Torus for revolute joints

### Workspace Analysis

The workspace of a robot is the set of all points reachable by the end-effector:

**Workspace**: W = {x ∈ R³ | ∃q ∈ Q such that x = f(q)}

Where Q is the joint space and f(q) is the forward kinematics function.

## Industrial Robot Configurations

### Cartesian Robots (PPP) - Mathematical Analysis

Cartesian robots have three prismatic joints with joint variables [d₁, d₂, d₃].

**Forward Kinematics**:
```
x = d₁
y = d₂
z = d₃
```

**Jacobian Matrix**:
```
J = [1  0  0]
    [0  1  0]
    [0  0  1]
```

**Advantages**:
- Linear workspace boundaries
- Constant precision across workspace
- Simple kinematics and control

**Disadvantages**:
- Limited reach-to-envelope ratio
- High structural requirements
- Large footprint for given workspace

### Cylindrical Robots (RPP) - Mathematical Analysis

Cylindrical robots have joint variables [θ, r, z].

**Forward Kinematics**:
```
x = r cos(θ)
y = r sin(θ)
z = z
```

**Jacobian Matrix**:
```
J = [-r sin(θ)   cos(θ)   0]
    [ r cos(θ)   sin(θ)   0]
    [    0         0      1]
```

**Workspace**: Cylindrical volume with radius r and height z

### Spherical/Polar Robots (RPR) - Mathematical Analysis

Spherical robots have joint variables [θ, φ, r].

**Forward Kinematics**:
```
x = r cos(θ) sin(φ)
y = r sin(θ) sin(φ)
z = r cos(φ)
```

**Jacobian Matrix**:
```
J = [-r sin(θ) sin(φ)   r cos(θ) cos(φ)   cos(θ) sin(φ)]
    [ r cos(θ) sin(φ)   r sin(θ) cos(φ)   sin(θ) sin(φ)]
    [        0         -r sin(φ)         cos(φ)        ]
```

## Advanced Manipulator Configurations

### SCARA Robots (RRP) - Mathematical Analysis

SCARA robots have joint variables [θ₁, θ₂, d₃].

**Forward Kinematics**:
```
x = a₁ cos(θ₁) + a₂ cos(θ₁ + θ₂)
y = a₁ sin(θ₁) + a₂ sin(θ₁ + θ₂)
z = d₃
```

**Inverse Kinematics**:
```
r² = x² + y²
θ₂ = ±arccos((r² - a₁² - a₂²) / (2a₁a₂))
θ₁ = arctan2(y, x) - arctan2(a₂ sin(θ₂), a₁ + a₂ cos(θ₂))
d₃ = z
```

**Jacobian Matrix**:
```
J = [-a₁sin(θ₁) - a₂sin(θ₁+θ₂)   -a₂sin(θ₁+θ₂)   0]
    [ a₁cos(θ₁) + a₂cos(θ₁+θ₂)    a₂cos(θ₁+θ₂)   0]
    [         0                        0         1]
```

### Articulated Robots (RRR) - Mathematical Analysis

6-DOF articulated robots are the most common industrial configuration.

**DH Parameters** for a typical 6-DOF robot:
| Joint | aᵢ | αᵢ | dᵢ | θᵢ |
|-------|----|----|----|----|
| 1     | 0  | π/2| d₁ | θ₁ |
| 2     | a₂ | 0  | 0  | θ₂ |
| 3     | a₃ | 0  | 0  | θ₃ |
| 4     | 0  | π/2| d₄ | θ₄ |
| 5     | 0  | -π/2|d₅ | θ₅ |
| 6     | 0  | 0  | d₆ | θ₆ |

**Inverse Kinematics Solution** for 6-DOF manipulator with spherical wrist:

The solution separates into position and orientation problems:
- First 3 joints solve for wrist center position
- Last 3 joints solve for end-effector orientation

```python
def inverse_kinematics_6dof(robot_params, target_pose):
    """
    Analytical inverse kinematics for 6-DOF robot with spherical wrist
    """
    # Extract position and orientation
    p_target = target_pose[:3, 3]
    R_target = target_pose[:3, :3]

    # Calculate wrist center position
    d6 = robot_params['d6']
    p_wrist_center = p_target - d6 * R_target[:3, 2]  # d6 * z-axis of end-effector

    # Solve for first 3 joints (position problem)
    x, y, z = p_wrist_center
    d1 = robot_params['d1']
    a2 = robot_params['a2']
    a3 = robot_params['a3']

    # Joint 1
    theta1 = np.arctan2(y, x)

    # Joint 2 and 3 (using geometric approach)
    r = np.sqrt(x**2 + y**2)
    D = (r**2 + (z-d1)**2 - a2**2 - a3**2) / (2*a2*a3)

    # Check for valid solution
    if abs(D) > 1:
        raise ValueError("Target position is outside workspace")

    theta3 = np.arctan2(np.sqrt(1-D**2), D)  # Elbow up solution
    theta2 = np.arctan2(z-d1, r) - np.arctan2(a3*np.sin(theta3), a2 + a3*np.cos(theta3))

    # Solve for last 3 joints (orientation problem)
    # Calculate T1, T2, T3 matrices and their inverse
    # Then compute R3_6 = R0_3.T @ R0_6
    # Finally solve for theta4, theta5, theta6

    return [theta1, theta2, theta3, theta4, theta5, theta6]
```

### Parallel Robots (Delta Robots) - Mathematical Analysis

Delta robots have three arms connected to a moving platform.

**Forward Kinematics** for Delta Robot:
The forward kinematics of a delta robot is complex and typically solved numerically due to the parallel mechanism constraints.

**Constraint Equations**:
For each arm i (i=1,2,3):
```
||B_i + R * P - A_i||² = l²
```

Where:
- A_i: Fixed base attachment point
- B_i: Moving platform attachment point
- P: Platform position
- R: Platform orientation matrix
- l: Arm length

## Mobile Robot Kinematics

### Differential Drive Kinematics

For a differential drive robot with wheel radius r and wheelbase L:

**Forward Kinematics**:
```
[ẋ]   [r/2  r/2] [ω_l]
[ẏ] = [0    0  ] [ω_r]
[θ̇]   [r/L -r/L] [   ]
```

Where ω_l and ω_r are left and right wheel angular velocities.

**Inverse Kinematics**:
```
[ω_l]   [1/r  0   L/r] [v_x]
[ω_r] = [1/r  0  -L/r] [v_y]
                    [ω_θ]
```

### Ackermann Steering Kinematics

For Ackermann steering (car-like motion):

**Kinematic Model**:
```
[ẋ]   [cos(θ)  0] [v]
[ẏ] = [sin(θ)  0] [φ]
[θ̇]   [0      1] [ ]
```

Where v is forward velocity and φ is steering angle.

## Humanoid Robot Configurations

### Biomechanical Modeling

Humanoid robots require complex biomechanical models to achieve human-like movement.

**Zero Moment Point (ZMP)**:
```
x_zmp = (Σ(m_i * g * x_i * z_i) - Σ(I_i * α_i * z_i)) / (Σ(m_i * g * z_i))
y_zmp = (Σ(m_i * g * y_i * z_i) - Σ(I_i * α_i * z_i)) / (Σ(m_i * g * z_i))
```

Where m_i, x_i, y_i, z_i are mass and position of link i, and I_i, α_i are moment of inertia and angular acceleration.

### Walking Pattern Generation

**Inverted Pendulum Model** for walking:
```
ẍ = g * x / z_c
```

Where z_c is the constant height of the center of mass.

**Trajectory Planning** for foot placement:
```
x(t) = x_0 * cosh(ω*t) + (ẋ_0/ω) * sinh(ω*t)
```

Where ω = sqrt(g/z_c) and x_0, ẋ_0 are initial position and velocity.

## Advanced Control for Different Configurations

### Cartesian Robots - Control Considerations

For Cartesian robots, feedforward control is particularly effective:

```python
class CartesianRobotController:
    def __init__(self, mass_matrix):
        self.M = mass_matrix  # Diagonal matrix for Cartesian robot
        self.kp = np.diag([100, 100, 100])  # Position gains
        self.kd = np.diag([20, 20, 20])    # Velocity gains

    def compute_control(self, q_desired, qd_desired, qdd_desired,
                       q_current, qd_current):
        # For Cartesian robots, M is constant and C = 0
        pos_error = q_desired - q_current
        vel_error = qd_desired - qd_current

        # Control law: τ = M(q_dd_des + Kp*e + Kd*ed)
        tau = self.M @ (qdd_desired + self.kp @ pos_error + self.kd @ vel_error)

        return tau
```

### Articulated Robot - Computed Torque Control

```python
class ArticulatedRobotController:
    def __init__(self, robot_model):
        self.model = robot_model
        self.kp = np.diag([50, 50, 50, 25, 15, 10])  # Joint-specific gains
        self.kd = np.diag([15, 15, 10, 8, 5, 3])    # Joint-specific gains

    def computed_torque_control(self, q_desired, qd_desired, qdd_desired,
                               q_current, qd_current):
        """
        Computed torque control with gravity compensation
        """
        # Calculate errors
        pos_error = q_desired - q_current
        vel_error = qd_desired - qd_current

        # Desired acceleration with feedback
        qdd_cmd = qdd_desired + self.kp @ pos_error + self.kd @ vel_error

        # Robot dynamics: τ = M(q)qdd + C(q,qd)qd + g(q)
        M = self.model.mass_matrix(q_current)
        C = self.model.coriolis_matrix(q_current, qd_current)
        G = self.model.gravity_vector(q_current)

        tau = M @ qdd_cmd + C @ qd_current + G

        return tau
```

## Configuration Optimization

### Workspace Optimization

Optimizing robot configuration for maximum workspace:

**Objective Function**:
```
maximize: Volume(W)
subject to: ||J(q)|| ≤ J_max ∀ q ∈ Q
```

Where J_max is the maximum Jacobian condition number (to avoid singularities).

### Payload Optimization

Optimizing configuration for maximum payload while maintaining workspace:

**Multi-objective Optimization**:
```
maximize: (Payload, Workspace_Volume)
subject to: τ_max ≥ ||τ_required||
```

## Specialized Configurations

### Cable-Driven Parallel Robots

Cable-driven robots use cables instead of rigid links:

**Kinematic Constraints**:
```
||P - A_i|| ≤ L_i
```

Where P is end-effector position, A_i is anchor point, and L_i is cable length.

**Dynamic Model**:
```
M(q)q̈ + C(q, q̇)q̇ + G(q) = τ - J^T F_cable
```

Where F_cable is the cable force vector and J is the Jacobian.

### Soft Robots

Soft robots use hyperelastic materials with complex constitutive models:

**Continuum Mechanics Model**:
```
σ = F * S * F^T
```

Where σ is Cauchy stress, F is deformation gradient, and S is second Piola-Kirchhoff stress.

```python
def select_robot_configuration(task_requirements, environment_constraints):
    """
    Algorithm for selecting optimal robot configuration
    """
    configurations = {
        'cartesian': {'workspace': 'rectangular', 'precision': 'high', 'speed': 'medium'},
        'cylindrical': {'workspace': 'cylindrical', 'precision': 'medium', 'speed': 'medium'},
        'spherical': {'workspace': 'spherical', 'precision': 'medium', 'speed': 'low'},
        'scara': {'workspace': 'circular', 'precision': 'high', 'speed': 'high'},
        'articulated': {'workspace': 'spherical', 'precision': 'medium', 'speed': 'medium'},
        'delta': {'workspace': 'hemispherical', 'precision': 'high', 'speed': 'very_high'}
    }

    # Weighted scoring based on requirements
    scores = {}
    for config, specs in configurations.items():
        score = 0
        for req, weight in task_requirements.items():
            if req in specs:
                # Normalize and weight each requirement
                normalized_score = normalize_requirement(specs[req], req)
                score += weight * normalized_score
        scores[config] = score

    return max(scores, key=scores.get)
```

## Advanced Analysis Tools

### Jacobian Analysis for Configuration Selection

```python
def analyze_configuration_jacobian(robot_config, workspace_points):
    """
    Analyze Jacobian properties across workspace for configuration evaluation
    """
    results = {
        'condition_numbers': [],
        'manipulability': [],
        'singularities': [],
        'dexterity': []
    }

    for point in workspace_points:
        try:
            jacobian = robot_config.compute_jacobian_at_point(point)

            # Condition number - indicates proximity to singularity
            cond_num = np.linalg.cond(jacobian)
            results['condition_numbers'].append(cond_num)

            # Manipulability measure
            manip = np.sqrt(np.linalg.det(jacobian @ jacobian.T))
            results['manipulability'].append(manip)

            # Check for singularities
            if cond_num > 1000:  # Threshold for singularity
                results['singularities'].append(point)

            # Dexterity measure (ratio of smallest to largest singular value)
            singular_values = np.linalg.svd(jacobian, compute_uv=False)
            dexterity = min(singular_values) / max(singular_values)
            results['dexterity'].append(dexterity)

        except Exception as e:
            print(f"Error analyzing point {point}: {e}")
            continue

    return results
```

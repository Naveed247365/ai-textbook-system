# Path Planning & Navigation (English Beginner Version)

## Chapter Overview

Path planning and navigation are essential capabilities that enable robots to move safely and efficiently through environments. These systems allow robots to determine optimal routes from a start to a goal while avoiding obstacles, considering constraints, and optimizing for various objectives like speed, safety, or energy. Navigation encompasses not just finding paths, but also executing them while handling real-world uncertainties and dynamic changes.

### What is Path Planning?

Path planning is the process of finding a valid route through an environment from a starting location to a destination. It involves:
- **Representing the environment** (maps, graphs, grids)
- **Considering robot constraints** (size, dynamics, capabilities)
- **Avoiding obstacles** while reaching the goal
- **Optimizing for criteria** like distance, safety, or time

**Types of Path Planning**:
- **Global Planning**: Computing a path before movement starts
- **Local Planning**: Adjusting path during movement based on sensors
- **Dynamic Planning**: Updating paths as environment changes

### What is Navigation?

Navigation is the broader capability of moving purposefully through space:
- **Localization**: Knowing where the robot is in its environment
- **Path Planning**: Determining the route to the goal
- **Path Following**: Executing the planned path precisely
- **Obstacle Avoidance**: Adjusting route when unexpected obstacles appear

**Navigation vs. Path Planning**:
- Path Planning: "What path should I take?"
- Navigation: "How do I follow the path while staying safe?"

## Environment Representation

### Grid-Based Maps

Grid maps divide the environment into discrete cells:

**2D Occupancy Grids**:
- Each cell indicates occupied, free, or unknown
- Simple but memory-intensive for large areas
- Good for basic navigation

**3D Volumetric Grids**:
- Extend to 3D space for aerial or complex navigation
- More detailed but computationally expensive
- Used for flying robots or 3D manipulation

```
Example 2D Grid:
S = Start, G = Goal, # = Obstacle, . = Free
+---+---+---+---+---+
| S | . | . | # | . |
+---+---+---+---+---+
| # | # | . | # | . |
+---+---+---+---+---+
| . | . | . | . | . |
+---+---+---+---+---+
| . | # | # | . | G |
+---+---+---+---+---+
```

### Topological Maps

Topological maps represent environments as graphs with nodes and connections:
- **Nodes**: Important locations (rooms, landmarks)
- **Edges**: Valid connections between locations
- **Advantages**: Compact representation, fast pathfinding
- **Use Cases**: Floor plans, building navigation

### Metric Maps

Metric maps provide precise geometric information:
- **2D Laser Scan Maps**: Accurate 2D representations
- **3D Point Clouds**: Detailed 3D environment models
- **Features**: Corners, edges, surfaces for navigation

## Classical Path Planning Algorithms

### A* Algorithm

A* is a widely-used algorithm that finds optimal paths efficiently:

**How A* Works**:
1. **Cost Function**: f(n) = g(n) + h(n)
   - g(n): Cost from start to current node
   - h(n): Heuristic estimate to goal (never overestimates)
   - f(n): Estimated total cost of path through node n
2. **Priority Queue**: Always expand lowest f(n) node
3. **Guarantee**: Optimal solution if h(n) is admissible

**A* Advantages**:
- Finds optimal paths
- Uses heuristics to guide search
- Complete (finds path if one exists)

**A* Disadvantages**:
- High memory usage
- Computationally expensive for large maps
- May explore many unnecessary nodes

```python
def simple_astar(start, goal, grid):
    """
    Simplified A* pathfinding implementation
    """
    open_list = [(0, start)]  # (f_score, position)
    closed_set = set()
    came_from = {}
    
    g_score = {start: 0}
    f_score = {start: heuristic(start, goal)}
    
    while open_list:
        # Get node with lowest f_score
        current_f, current = heapq.heappop(open_list)
        
        if current == goal:
            # Reconstruct path
            path = []
            while current in came_from:
                path.append(current)
                current = came_from[current]
            path.reverse()
            return path
        
        closed_set.add(current)
        
        # Check 4-directional neighbors
        for dx, dy in [(0,1), (0,-1), (1,0), (-1,0)]:
            neighbor = (current[0] + dx, current[1] + dy)
            
            # Check if neighbor is valid
            if (neighbor[0] < 0 or neighbor[0] >= len(grid) or 
                neighbor[1] < 0 or neighbor[1] >= len(grid[0]) or
                neighbor in closed_set or
                grid[neighbor[0]][neighbor[1]] == 1):  # 1 = obstacle
                continue
            
            tentative_g = g_score[current] + 1
            
            if neighbor not in [item[1] for item in open_list]:
                # Add to open list
                g_score[neighbor] = tentative_g
                f_score[neighbor] = g_score[neighbor] + heuristic(neighbor, goal)
                heapq.heappush(open_list, (f_score[neighbor], neighbor))
                came_from[neighbor] = current
            elif tentative_g < g_score[neighbor]:
                # Better path found, update
                g_score[neighbor] = tentative_g
                f_score[neighbor] = g_score[neighbor] + heuristic(neighbor, goal)
                came_from[neighbor] = current
    
    return []  # No path found

def heuristic(pos1, pos2):
    """Manhattan distance heuristic"""
    return abs(pos1[0] - pos2[0]) + abs(pos1[1] - pos2[1])
```

### Dijkstra's Algorithm

Dijkstra's algorithm finds shortest paths but doesn't use heuristics:
- **Cost Only**: g(n) function (actual cost from start)
- **Complete**: Guaranteed optimal if solution exists
- **Slower Than A***: Explores more nodes
- **Useful When**: No good heuristic available

## Sampling-Based Methods

### Rapidly-exploring Random Trees (RRT)

RRTs are excellent for high-dimensional spaces and complex constraints:

**How RRT Works**:
1. Start with tree containing only start position
2. Sample random point in environment
3. Find nearest point in existing tree
4. Extend tree toward random point (avoiding obstacles)
5. Repeat until goal is reached or time limit

**RRT Advantages**:
- Good for high-dimensional spaces
- Handles complex kinematic constraints
- Probabilistically complete (finds path if exists)
- Works well with non-holonomic robots

**RRT Disadvantages**:
- Not optimal (paths often suboptimal)
- Biased toward unexplored areas
- Slow convergence to optimal solution

```python
class RRT:
    def __init__(self, start, goal, bounds, obstacles):
        self.start = start
        self.goal = goal
        self.bounds = bounds  # [[min_x, max_x], [min_y, max_y]]
        self.obstacles = obstacles
        self.tree = [start]
        self.parents = [-1]  # Parent indices
        self.step_size = 0.1  # Distance to extend each step
    
    def plan(self):
        """Plan path using RRT algorithm"""
        while self.tree:  # Continue until goal reached
            # Sample random point
            rand_point = self.sample_random()
            
            # Occasionally bias toward goal (e.g., 10% of time)
            if np.random.random() < 0.1:
                rand_point = self.goal
            
            # Find nearest node in tree
            nearest_idx = self.nearest_node(rand_point)
            nearest_node = self.tree[nearest_idx]
            
            # Extend toward random point
            new_node = self.extend_toward(nearest_node, rand_point)
            
            if new_node is not None:
                self.tree.append(new_node)
                self.parents.append(nearest_idx)
                
                # Check if goal reached
                if self.distance(new_node, self.goal) < self.step_size:
                    return self.extract_path()
        
        return None  # No path found
    
    def sample_random(self):
        """Sample random point in environment bounds"""
        x = np.random.uniform(self.bounds[0][0], self.bounds[0][1])
        y = np.random.uniform(self.bounds[1][0], self.bounds[1][1])
        return [x, y]
    
    def nearest_node(self, point):
        """Find index of nearest node in tree to given point"""
        distances = [self.distance(point, node) for node in self.tree]
        return np.argmin(distances)
    
    def extend_toward(self, from_node, to_point):
        """Try to extend tree from from_node toward to_point"""
        direction = np.array(to_point) - np.array(from_node)
        distance = np.linalg.norm(direction)
        
        if distance < self.step_size:
            candidate = to_point
        else:
            # Normalize direction and scale to step size
            direction = direction / distance
            candidate = list(np.array(from_node) + self.step_size * direction)
        
        # Check for collision with obstacles
        if not self.check_collision(from_node, candidate):
            return candidate
        else:
            return None  # Collision detected
    
    def check_collision(self, point1, point2):
        """Check if line segment between points collides with any obstacle"""
        # Simple implementation - check if points are inside obstacles
        # In practice, would use more sophisticated collision detection
        return False
    
    def extract_path(self):
        """Extract path from goal back to start using parent pointers"""
        path = [self.goal]
        current_idx = len(self.tree) - 1
        
        while current_idx != -1:
            path.append(self.tree[current_idx])
            current_idx = self.parents[current_idx]
        
        path.reverse()
        return path
```

### Probabilistic Roadmap (PRM)

PRM pre-computes a roadmap of possible connections:

**How PRM Works**:
1. Sample random free configurations in environment
2. Connect nearby configurations (if collision-free)
3. Store as graph structure
4. Use graph search (like Dijkstra's) to find path between start/goal

**PRM Advantages**:
- Good for multiple queries in same environment
- Pre-processing allows fast path queries
- Handles high-dimensional configuration spaces

**PRM Disadvantages**:
- Memory-intensive for dense graphs
- May miss narrow passages
- Less effective for dynamic environments

## Local Path Planning and Obstacle Avoidance

### Potential Field Methods

Potential field methods treat navigation as a force-based system:
- **Attractive Force**: Pulls robot toward goal
- **Repulsive Force**: Pushes robot away from obstacles
- **Resultant Force**: Robot moves in combined force direction

**Advantages**:
- Simple to implement and understand
- Reactive to local obstacles
- Real-time capable

**Disadvantages**:
- Gets trapped in local minima
- Oscillations in cluttered environments
- Difficult to tune parameters

### Vector Field Histogram (VFH)

VFH analyzes local environment as a histogram of possible directions:

**How VFH Works**:
1. Create polar histogram of obstacle density around robot
2. Identify safe directions with sufficient clearance
3. Select preferential direction toward goal

**VFH Advantages**:
- Efficient local obstacle avoidance
- Good for real-time navigation
- Handles sensor noise well

**VFH Disadvantages**:
- Local minima possible
- Limited look-ahead
- Requires good sensor data

```python
def vector_field_histogram(obstacle_distances, robot_heading, goal_direction):
    """
    Vector Field Histogram for local obstacle avoidance
    """
    # Create histogram of obstacle distances by angle
    num_bins = 18  # 20-degree bins (360/20)
    histogram = np.zeros(num_bins)
    
    # Populate histogram based on obstacle data
    for i, distance in enumerate(obstacle_distances):
        angle_bin = int((i * (360 / len(obstacle_distances))) / (360 / num_bins))
        if angle_bin >= num_bins:
            angle_bin = num_bins - 1
        histogram[angle_bin] += 1.0 / (distance + 1e-6)  # Closer obstacles have higher weight
    
    # Find safe directions (low obstacle density)
    safe_threshold = np.mean(histogram) * 0.5  # Below average is safe
    safe_angles = np.where(histogram < safe_threshold)[0]
    
    if len(safe_angles) > 0:
        # Among safe angles, choose one closest to goal direction
        goal_bin = int(goal_direction / (360 / num_bins))
        closest_safe = safe_angles[np.argmin(np.abs(safe_angles - goal_bin))]
        
        # Return selected direction
        return closest_safe * (360 / num_bins)
    else:
        # No safe directions - rotate in place
        return robot_heading
```

### Dynamic Window Approach (DWA)

DWA evaluates feasible velocities in real-time:

**How DWA Works**:
1. Consider all dynamically feasible velocity commands
2. Simulate short-term trajectories for each command
3. Score trajectories based on goal approach, obstacle avoidance, and speed
4. Select best-scoring trajectory

**DWA Advantages**:
- Considers robot dynamics
- Real-time capable
- Balances multiple objectives

**DWA Disadvantages**:
- Computationally expensive
- Short planning horizon
- Requires accurate dynamic model

## Navigation Systems

### Simultaneous Localization and Mapping (SLAM)

SLAM allows robots to build maps while determining their location:

**Key Components**:
- **Mapping**: Creating environment representation
- **Localization**: Determining robot pose in map
- **Data Association**: Matching sensor observations to map features

**SLAM Types**:
- **2D SLAM**: For ground robots on flat surfaces
- **3D SLAM**: For flying or complex terrain robots
- **Visual SLAM**: Using cameras as primary sensors
- **LiDAR SLAM**: Using laser scanners

### Robot Operating System (ROS) Navigation Stack

ROS provides standardized navigation tools:

**Core Components**:
- **Global Planner**: Generates overall route
- **Local Planner**: Handles immediate obstacle avoidance
- **Costmap**: Represents obstacles and safe zones
- **Recovery Behaviors**: Handles navigation failures

**Navigation Process**:
1. Transform goal to map coordinates
2. Global planner computes route
3. Local planner executes immediate navigation
4. Sensors update obstacle information
5. Repeat until goal reached

## Practical Navigation Considerations

### Robot Physical Constraints

Navigation must account for robot dynamics:
- **Size**: Robot footprint affects navigable areas
- **Kinematics**: Differential drive vs. omnidirectional
- **Dynamics**: Acceleration and velocity limits
- **Sensors**: Field of view and accuracy limitations

### Environmental Uncertainty

Real environments present challenges:
- **Dynamic Obstacles**: Moving people, vehicles, doors
- **Sensor Noise**: Imperfect perception of environment
- **Changing Conditions**: Lighting, weather, furniture
- **Uncertain Maps**: Incomplete or outdated information

### Safety Considerations

Navigation systems prioritize safety:
- **Collision Avoidance**: Never hit obstacles or humans
- **Conservative Planning**: Maintain safety margins
- **Emergency Stops**: Immediate halt when necessary
- **Fail-Safe Behaviors**: Safe responses to system failures

## Path Planning Challenges

### Computational Complexity

Path planning can be computationally intensive:
- **Large Environments**: Require more computation to search
- **High Resolution**: Finer grids increase search space exponentially
- **Real-Time Requirements**: Must plan quickly for mobile robots
- **Dynamic Environments**: Constant replanning needed

### Completeness vs. Optimality

Trade-offs between finding any solution vs. optimal solution:
- **Complete**: Algorithm will find solution if one exists
- **Optimal**: Algorithm finds best possible solution
- **Practical**: Often compromise for computational efficiency

### Local Minima

Robots may get stuck in areas with no clear path to goal:
- **Potential Fields**: Robot trapped between obstacles and goal
- **Local Algorithms**: Cannot see global picture
- **Solutions**: Global planning, alternative routes, or random walks

## Evaluation Metrics

### Path Quality Metrics

**Optimality**: How close to shortest possible path
- **Path Length**: Total distance traveled
- **Computed vs. Optimal**: Ratio of actual to optimal path

**Smoothness**: How smooth the path is for robot execution
- **Curvature**: Sharp turns require complex maneuvers
- **Continuity**: Continuous velocity and acceleration

**Safety**: How well path avoids obstacles
- **Clearance**: Distance maintained from obstacles
- **Risk Assessment**: Probability of collision along path

### Performance Metrics

**Time**: How quickly path is computed
- **Planning Time**: Duration to find solution
- **Execution Time**: Time to traverse path

**Success Rate**: Percentage of successful navigations
- **Goal Reached**: Robot successfully reaches destination
- **Navigation Failure**: Robot gets stuck or takes too long

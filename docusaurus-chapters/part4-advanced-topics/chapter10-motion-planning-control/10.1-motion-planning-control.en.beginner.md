# Motion Planning & Control (English Beginner Version)

## Chapter Overview

Motion planning and control form the backbone of robotics, enabling robots to move effectively and safely in their environments. Motion planning involves determining the optimal path from a starting location to a goal while avoiding obstacles. Control involves executing those planned motions while maintaining stability and achieving desired performance. These systems work together to give robots the ability to navigate and manipulate objects safely.

### What is Motion Planning?

Motion planning is the process of determining how a robot should move from its current position to a desired goal position. Think of it as giving directions to a lost traveler, but instead of roads and streets, we consider the robot's physical constraints and environmental obstacles.

**Key Components**:
- **Configuration Space**: All possible positions/orientations the robot can take
- **Free Space**: Areas where the robot can move without collisions
- **Obstacles**: Areas the robot must avoid
- **Path**: Sequence of connected positions leading to the goal

### What is Motion Control?

Motion control is the process of commanding robot actuators to execute planned motions. It involves:
- **Trajectory Following**: Following a planned path precisely
- **Stability**: Maintaining balance and control
- **Accuracy**: Achieving desired positions with minimal error
- **Safety**: Preventing dangerous movements or collisions

## Basic Motion Planning Concepts

### Configuration Space (C-Space)

The configuration space represents all possible states of a robot. For a 2D point robot, it's simply the 2D plane. For more complex robots, it includes all joint angles and positions.

**Simple Example - 2D Point Robot**:
- **Position**: (x, y) coordinates
- **C-Space**: 2D plane representing all possible (x, y) positions

**Complex Example - 2-Joint Robotic Arm**:
- **Configuration**: (θ₁, θ₂) joint angles
- **C-Space**: 2D torus (donut shape) representing all possible joint angle combinations

### Path vs. Trajectory

**Path**: Geometric route from start to goal (shape only)
- Defines WHERE the robot should go
- No time information

**Trajectory**: Path with timing information
- Defines WHERE and WHEN the robot should be at each point
- Includes velocity and acceleration profiles

### Obstacle Avoidance

Obstacles are areas that the robot must not enter. Planning algorithms must navigate around them.

**Types of Obstacles**:
- **Static**: Fixed position (walls, furniture)
- **Dynamic**: Moving obstacles (people, other robots)
- **Uncertain**: Locations that may change (doors, movable objects)

## Classic Motion Planning Algorithms

### Grid-Based Planning

Grid-based planning divides the environment into discrete cells:

**A* Algorithm**:
A* finds the shortest path using heuristics:
- **Cost Function**: f(n) = g(n) + h(n)
  - g(n): Cost from start to current node
  - h(n): Heuristic estimate to goal
- **Advantages**: Optimal and guarantees path if one exists
- **Disadvantages**: Computationally expensive for large grids

```python
def simple_astar(grid, start, goal):
    """
    Simplified A* pathfinding algorithm
    """
    open_list = [(start, 0)]  # (location, cost)
    closed_set = set()
    came_from = {}
    
    # Estimated distance to goal (straight-line distance)
    def heuristic(a, b):
        return abs(a[0] - b[0]) + abs(a[1] - b[1])
    
    while open_list:
        # Get node with lowest cost
        current, cost = open_list.pop(0)
        
        if current == goal:
            # Reconstruct path
            path = []
            while current in came_from:
                path.append(current)
                current = came_from[current]
            path.reverse()
            return path
        
        closed_set.add(current)
        
        # Check neighbors (up, down, left, right)
        for dx, dy in [(0,1), (0,-1), (1,0), (-1,0)]:
            neighbor = (current[0] + dx, current[1] + dy)
            
            # Check if neighbor is valid
            if (neighbor[0] < 0 or neighbor[0] >= len(grid) or 
                neighbor[1] < 0 or neighbor[1] >= len(grid[0]) or
                neighbor in closed_set or
                grid[neighbor[0]][neighbor[1]] == 1):  # 1 = obstacle
                continue
            
            tentative_cost = cost + 1
            
            # Add to open list if not already there
            open_list.append((neighbor, tentative_cost))
            came_from[neighbor] = current
    
    return []  # No path found
```

### Visibility Graph

Connects start, goal, and obstacle vertices with direct paths:

**How it works**:
1. Identify all obstacle corner points
2. Connect points with straight lines that don't cross obstacles
3. Use graph search (like Dijkstra) to find shortest path

**Advantages**: Optimal for polygonal obstacles
**Disadvantages**: Computationally intensive for complex environments

## Sampling-Based Methods

### Rapidly-exploring Random Trees (RRT)

RRTs grow trees by randomly sampling the configuration space:

**Algorithm Steps**:
1. Start with tree containing only start position
2. Sample random point in space
3. Find nearest point in tree
4. Extend tree toward random point (without collision)
5. Repeat until goal is reached or time limit

**Advantages**:
- Good for high-dimensional spaces
- Handles complex constraints
- Probabilistically complete (will find path if one exists)

**Disadvantages**:
- Not optimal (paths may be longer than necessary)
- Biased toward unexplored areas

```python

class RRT:
    def __init__(self, start, goal, bounds, obstacles):
        self.start = start
        self.goal = goal
        self.bounds = bounds  # [[min_x, max_x], [min_y, max_y]]

        self.step_size = 0.1  # Distance to extend each step
    
    def sample_random(self):
        """Sample random point in configuration space"""
        x = np.random.uniform(self.bounds[0][0], self.bounds[0][1])
        y = np.random.uniform(self.bounds[1][0], self.bounds[1][1])
        return [x, y]
    
    def nearest_node(self, point):

        distances = [np.linalg.norm(np.array(point) - np.array(node)) 
                     for node in self.tree]
        return np.argmin(distances)
    
    def extend_towards(self, from_node, to_point):

        direction = np.array(to_point) - np.array(from_node)

            if success:
                if np.linalg.norm(np.array(self.tree[-1]) - np.array(self.goal)) < self.step_size:

                    return self.extract_path()
        
        return None  # No path found
    
    def extract_path(self):
        """Extract path from tree by following parent pointers"""
        path = [self.goal]
        current_idx = len(self.tree) - 1
        
        while current_idx != -1:
            path.append(self.tree[current_idx])
            current_idx = self.parents[current_idx]
        
        path.reverse()
        return path
```

### Probabilistic Roadmap (PRM)

PRM pre-builds a roadmap of possible paths:

**How it works**:
1. Sample random feasible configurations
2. Connect nearby configurations (if collision-free)
3. Use graph search to find path between start and goal

**Advantages**:
- Good for repeated queries in same environment
- Efficient for preprocessing

**Disadvantages**:
- Memory intensive
- May miss narrow passages

## Motion Control Fundamentals

### Feedback Control

Feedback control uses sensor measurements to correct robot behavior:

**Components**:
- **Reference Input**: Desired robot state (position, velocity)
- **Controller**: Computes corrective commands
- **Plant**: Robot dynamics
- **Sensor**: Measures actual robot state
- **Error**: Difference between desired and actual states

### PID Control

PID (Proportional-Integral-Derivative) control is fundamental in robotics:

**Control Law**:
u(t) = K_p * e(t) + K_i * ∫e(t)dt + K_d * de(t)/dt

Where:
- u(t): Control output
- e(t): Error signal (desired - actual)
- K_p: Proportional gain
- K_i: Integral gain
- K_d: Derivative gain

**Tuning PID Parameters**:
- **K_p**: Higher values = faster response but potential oscillation
- **K_i**: Eliminates steady-state error but can cause instability
- **K_d**: Improves stability and reduces overshoot

```python
class PIDController:
    def __init__(self, kp, ki, kd):
        self.kp = kp
        self.ki = ki
        self.kd = kd
        self.previous_error = 0
        self.integral = 0
        self.derivative = 0
    
    def update(self, error, dt):
        """
        Update PID controller with new error
        
        Args:
            error: Current error (desired - actual)
            dt: Time step
        
        Returns:
            Control output
        """
        # Proportional term
        p_term = self.kp * error
        
        # Integral term (accumulate error)
        self.integral += error * dt
        i_term = self.ki * self.integral
        
        # Derivative term (rate of error change)
        self.derivative = (error - self.previous_error) / dt
        d_term = self.kd * self.derivative
        
        # Store current error for next derivative calculation
        self.previous_error = error
        
        # Total control output
        output = p_term + i_term + d_term
        return output

# Example: Controlling robot position
def control_robot_position(target_position, current_position, pid_controller, dt):
    """Control robot to reach target position"""
    # Calculate position error
    error = target_position - current_position
    
    # Get control command from PID
    control_command = pid_controller.update(error, dt)
    
    # Apply control command to robot (this would interface with actual robot)
    # robot.apply_command(control_command)
    
    return control_command
```

## Path Following and Trajectory Tracking

### Pure Pursuit Controller

Pure pursuit is a popular path-following algorithm:

**Concept**: Robot aims toward a look-ahead point on the path

**Algorithm**:
1. Find point ahead on path at distance L
2. Calculate angle to that point
3. Use bicycle model to compute steering command

```python
class PurePursuitController:
    def __init__(self, look_ahead_distance):
        self.look_ahead = look_ahead_distance
        self.previous_idx = 0
    
    def find_look_ahead_point(self, path, robot_pos):
        """Find point on path at look-ahead distance from robot"""
        # Start from previous position to be more efficient
        for i in range(self.previous_idx, len(path)):
            distance = np.linalg.norm(np.array(path[i]) - np.array(robot_pos))
            if distance >= self.look_ahead:
                self.previous_idx = i  # Remember for next iteration
                return path[i]
        
        # If reached end of path, return the last point
        return path[-1]
    
    def calculate_steering(self, robot_pos, robot_heading, look_ahead_point):
        """Calculate steering command for pure pursuit"""
        # Vector from robot to look-ahead point
        to_point = np.array(look_ahead_point) - np.array(robot_pos)
        
        # Angle between robot heading and vector to point
        angle_diff = np.arctan2(to_point[1], to_point[0]) - robot_heading
        
        # Normalize angle to [-pi, pi]
        angle_diff = (angle_diff + np.pi) % (2 * np.pi) - np.pi
        
        # Calculate steering command (simplified bicycle model)
        # Steering ~ angle_diff / look_ahead_distance
        steering_command = np.arctan2(2.0 * self.look_ahead * np.sin(angle_diff), 1.0)
        
        return steering_command

def follow_path(robot_pos, robot_heading, path, controller):
    """Follow path using pure pursuit controller"""
    look_ahead_point = controller.find_look_ahead_point(path, robot_pos)
    steering_command = controller.calculate_steering(
        robot_pos, robot_heading, look_ahead_point
    )
    
    # Apply steering command to robot
    # robot.steer(steering_command)
    
    return steering_command
```

### Stanley Controller

Another popular path-following method that corrects for both heading and cross-track error:

**Algorithm**:
- **Heading Error**: Difference between robot heading and path heading
- **Cross-track Error**: Lateral distance to path
- **Total Correction**: Combination of both errors

## Robot Control Structures

### Open-Loop vs. Closed-Loop

**Open-Loop Control**:
- Executes predetermined commands without feedback
- Simple and fast
- No correction for errors or disturbances

**Closed-Loop Control**:
- Uses sensor feedback to correct errors
- More robust to disturbances
- More complex but more accurate

### Cascade Control

Cascade control uses multiple PID controllers in sequence:

**Outer Loop**: Position control (desired position → desired velocity)
**Inner Loop**: Velocity control (desired velocity → desired force/torque)

This approach provides better stability and performance.

## Obstacle Avoidance

### Reactive Methods

Reactive methods respond immediately to detected obstacles:

**Vector Field Histogram (VFH)**:
- Analyzes local environment as polar histogram
- Identifies safe directions to move
- Responsive but might get trapped in local minima

**Potential Fields**:
- Attractive force toward goal
- Repulsive force from obstacles
- Robot moves in direction of combined force

```python
def potential_field_navigation(robot_pos, goal_pos, obstacles):
    """Simple potential field navigation"""
    attractive_force = [0, 0]
    repulsive_force = [0, 0]
    
    # Attractive force toward goal
    goal_direction = np.array(goal_pos) - np.array(robot_pos)
    attractive_force = 0.5 * goal_direction  # Scale factor
    
    # Repulsive forces from obstacles
    for obstacle in obstacles:
        obs_direction = np.array(robot_pos) - np.array(obstacle)
        distance = np.linalg.norm(obs_direction)
        
        if distance < 2.0:  # Influence distance
            # Repulsive force increases as robot gets closer
            repulsive_strength = 1.0 / (distance**2) if distance > 0 else float('inf')
            repulsive_force += repulsive_strength * obs_direction / distance
    
    # Total force
    total_force = attractive_force + repulsive_force
    
    # Normalize and return direction vector
    if np.linalg.norm(total_force) > 0:
        return total_force / np.linalg.norm(total_force)
    else:
        return [0, 0]  # No movement if forces cancel out
```

### Deliberative Methods

Deliberative methods plan globally and consider the entire environment:
- **Recalculate path** when obstacles are detected
- **Consider global optimality** rather than local reactions
- **More computationally intensive** but globally optimal

## Applications in Robotics

### Mobile Robot Navigation

Motion planning and control enable:
- **Autonomous Navigation**: Robots move without human guidance
- **Obstacle Avoidance**: Safely navigate around unexpected obstacles
- **Multi-floor Navigation**: Handle elevators and stairs

For robotic arms and manipulators:

For walking robots:

- **Gait Planning**: Generate efficient walking patterns

## Challenges and Considerations

### Real-Time Performance

Motion planning and control must operate in real-time:
- **Computational Efficiency**: Algorithms must run fast
- **Sensor Delays**: Account for processing time of sensor data
- **Actuator Dynamics**: Consider the physical limitations of robot hardware

### Uncertainty and Noise

Real robots face:
- **Sensor Noise**: Imperfect measurements
- **Model Uncertainty**: Differences between model and reality
- **Environmental Changes**: Dynamic obstacles and conditions
- **Actuator Uncertainty**: Imperfect control execution

### Safety Considerations

Safety is paramount in motion planning and control:
- **Collision Avoidance**: Never hit obstacles or humans
- **Physical Limits**: Stay within actuator capabilities
- **Emergency Stops**: Have fail-safe mechanisms
- **Certification**: Meet safety standards for deployment

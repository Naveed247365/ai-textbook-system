# ROS2 ا Essentials (اردو ایڈوانسڈ ورژن)

## باب کا جائزہ

ROS2 (روبوٹ آپریٹنگ سسٹم 2) روبوٹ آپریٹنگ سسٹم کی مکمل دوبارہ ڈیزائن کی نمائندگی کرتا ہے جس میں بہتر سیکیورٹی، ریل ٹائم صلاحیتیں، اور بہتر مڈل ویئر لچک شامل ہیں۔ ڈیٹا ڈسٹری بیوشن سروس (DDS) معیار پر تعمیر شدہ، ROS2 قابل اعتماد کمیونیکیشن، کوالٹی آف سروس (QoS) کنٹرولز، اور مشن کے اہم روبوٹک ایپلی کیشنز کے لیے بہتر ناکامی برداشت کی صلاحیت فراہم کرتا ہے۔

### ROS1 سے ROS2 میں معماری کی تبدیلی

ROS2 ROS1 کی بنیادی حدود کو مندرجہ ذیل کے ذریعے حل کرتا ہے:

- **DDS انضمام**: ROS1 کے TCPROS/UDPROS کو معیاری DDS کے ساتھ تبدیل کرنا
- **ریل ٹائم سپورٹ**: قابل شناخت عمل اور محدود میموری تخصیص
- **مولٹی-روبوٹ سسٹم**: واحد ناکامی کے نقاط کے بغیر متعدد روبوٹس کے لیے اصلی سپورٹ
- **سیکیورٹی**: تصدیق، اختیارات، اور خفیہ کاری کی اندرونی صلاحیات

### مڈل ویئر آزادی

ROS2 مواصلات کو ROS مڈل ویئر انٹر فیس (RMW) کے ذریعے ایبسٹریکٹ کرتا ہے، جس سے مندرجہ ذیل ممکن ہوتا ہے:

- **ملٹی-DDS ایمپلیمنٹیشن**: مختلف DDS وینڈرز کی حمایت (Fast DDS، Cyclone DDS، RTI Connext)
- **اپنی مرضی کا مڈل ویئر**: اپنی مرضی کی کمیونیکیشن لیئرز کو ایمپلیمنٹ کرنے کی امکان
- **کارکردگی کی بہتری**: مخصوص ضروریات کی بنیاد پر مڈل ویئر کا انتخاب

## بنیادی معماری

### نوڈ معماری

ROS2 نوڈس درج ذیل معماری پیٹرنز کو لاگو کرتے ہیں:

**نوڈ اجزاء:**
- **ایگزیکیوٹر**: نوڈ ایکسیکوشن اور کال بیک شیڈولنگ کا نظم کرتا ہے
- **نوڈ انٹرفیس**: نوڈ لائف سائیکل اور انٹروسپیکشن کا انتظام کرتا ہے
- **پیرامیٹر سرور**: متحرک پیرامیٹر مینجمنٹ فراہم کرتا ہے
- **کلاک انٹرفیس**: مختلف وقت کے ڈومینز کی حمایت کرتا ہے (سسٹم، شبیہہ، مستحکم)

### کمیونیکیشن انفراسٹرکچر

#### DDS-بیسڈ کمیونیکیشن

DDS (ڈیٹا ڈسٹری بیوشن سروس) فراہم کرتا ہے:

- **ڈیٹا-سینٹرک**: مواصلات اختتامی نقاط کے بجائے ڈیٹا سیمینٹکس پر مبنی
- **دراصلیت**: پبلشرز اور سبسکرائبرز کی خودکار دراصلیت
- **ٹائپ-سیفٹی**: میسیجز کی کمپائل ٹائم ٹائپ چیکنگ
- **دیوقی**: دیر سے شامل ہونے والے سبسکرائبرز کے لیے میسیج استحکام

#### کوالٹی آف سروس (QoS) کنٹرولز

QoS پالیسیز کمیونیکیشن کے طرز عمل پر باریک ترتیبات فراہم کرتی ہیں:

**قابل اعتماد پالیسی:**
- `RMW_QOS_POLICY_RELIABILITY_RELIABLE`: تمام میسیجز ترسیل (ساتھ میں دوبارہ کوشش)
- `RMW_QOS_POLICY_RELIABILITY_BEST_EFFORT`: میسیجز ضمانت کے بغیر ترسیل

**دیوقی پالیسی:**
- `RMW_QOS_POLICY_DURABILITY_TRANSIENT_LOCAL`: دیر سے شامل ہونے والوں کے لیے میسیجز استحکام
- `RMW_QOS_POLICY_DURABILITY_VOLATILE`: صرف موجودہ سبسکرائبرز کے لیے میسیجز

**ہسٹری پالیسی:**
- `RMW_QOS_POLICY_HISTORY_KEEP_LAST`: N سب سے حالیہ میسیجز رکھیں
- `RMW_QOS_POLICY_HISTORY_KEEP_ALL`: تمام موصول میسیجز رکھیں

**لائیولینس پالیسی:**
- `RMW_QOS_POLICY_LIVELINESS_AUTOMATIC`: میسیج شائع ہونے کی بنیاد پر
- `RMW_QOS_POLICY_LIVELINESS_MANUAL_BY_TOPIC`: صراحت کے ساتھ لائیولینس کا اظہار

### میموری مینجمنٹ

ROS2 صفر-کاپی میموری مینجمنٹ کو مندرجہ ذیل کے ذریعے نافذ کرتا ہے:

- **انٹرا-پروسیس کمیونیکیشن**: ایک ہی عمل میں نوڈس کے درمیان براہ راست میموری شیئرنگ
- **شیئرڈ میموری ٹرانسپورٹ**: انٹر-پروسیس کمیونیکیشن کے لیے میموری-میپڈ فائلز
- **ROS مڈل ویئر انٹرفیس**: میموری تخصیص کی پالیسیز کے لیے ایبسٹریکشن لیئر

## جامع کمیونیکیشن پیٹرنز

### نوڈس اور کمپوننٹس

#### کمپوننٹ آرکیٹیکچر

ROS2 کارکردگی کی بہتری کے لیے کمپوننٹ-بیسڈ آرکیٹیکچر کی حمایت کرتا ہے:

```cpp
#include "rclcpp/rclcpp.hpp"

class MyComponent : public rclcpp::Node
{
public:
    MyComponent(const rclcpp::NodeOptions & options) : Node("my_component", options) 
    {
        // کمپوننٹ ایمپلیمنٹیشن
    }
};
```

#### کمپوزیشن

کمپوننٹ کمپوزیشن متعدد نوڈس کو ایک ہی عمل میں چلانے کی اجازت دیتا ہے:

```bash
# ایک ہی عمل میں کمپوننٹس چلائیں
ros2 run rclcpp_components component_container
ros2 component load my_container my_package MyComponent
```

### سروسز اور ایکشنز

#### جامع سروس خصوصیات

**سروس ٹائپ سپورٹ:**
- **ریکوئسٹ/ریسپانس**: کال بیکس کے ساتھ مترتب کمیونیکیشن
- **ایسک سروس کلائنٹس**: غیر مسدود سروس کالز
- **سروس انٹروسپیکشن**: رن ٹائم سروس دراصلیت اور مانیٹرنگ

#### ایکشن آرکیٹیکچر

ایکشنز مقصد-مند کمیونیکیشن فراہم کرتے ہیں جس میں فیڈ بیک شامل ہے:

```cpp
// ایکشن سرور ایمپلیمنٹیشن
class FibonacciActionServer : public rclcpp::Node
{
    rclcpp_action::Server<Fibonacci>::SharedPtr action_server_;
    
    rclcpp_action::GoalResponse handle_goal(
        const rclcpp_action::GoalUUID & uuid,
        std::shared_ptr<const Fibonacci::Goal> goal);
    
    rclcpp_action::CancelResponse handle_cancel(
        const std::shared_ptr<GoalHandleFibonacci> goal_handle);
};
```

## ریل ٹائم پروگرامنگ

### ریل ٹائم کے خیالات

ROS2 ریل ٹائم سسٹم کی حمایت مندرجہ ذیل کے ذریعے کرتا ہے:

- **قابل شناخت شیڈولنگ**: ترتیبات قابل تھریڈ ترجیحات اور تعلق
- **میموری الاؤکیشن**: متحرک تخصیص سے بچنے کے لیے فکسڈ-سائز الاؤکیٹرز
- **ٹائمر انٹیگریشن**: درست وقت کے لیے ہائی ریزولوشن ٹائمرز

### ریل ٹائم ایکسیکوشن

```cpp
// مثال ریل ٹائم نوڈ کنفیگریشن
rclcpp::executors::MultiThreadedExecutor executor(
    rclcpp::executor::ExecutorArgs(), 
    2  // تھریڈ کاؤنٹ
);

// ریل ٹائم ترجیح سیٹ کریں
struct sched_param param;
param.sched_priority = 80;
pthread_setschedparam(pthread_self(), SCHED_FIFO, &param);
```

## بلڈ سسٹم اور انحصار

### Ament بلڈ سسٹم

Ament ROS2 کے لیے ایک ماڈولر بلڈ سسٹم فراہم کرتا ہے:

**ament_python:**

### انحصار مینجمنٹ

ROS2 بلڈ اور انحصار مینجمنٹ کے لیے colcon استعمال کرتا ہے:

```bash
# مخصوص پیکیجز کے ساتھ تعمیر کریں
colcon build --packages-select my_package1 my_package2

# مخصوص CMake آپشنز کے ساتھ تعمیر کریں
colcon build --cmake-args -DCMAKE_BUILD_TYPE=Release

# مخصوص تھریڈ کاؤنٹ کے ساتھ موازی میں تعمیر کریں
colcon build --parallel-workers 4
```

## جامع خصوصیات

### لائف سائیکل نوڈس

لائف سائیکل نوڈس جامع سسٹم کے لیے اسٹیٹ مینجمنٹ فراہم کرتے ہیں:

```cpp
class LifecycleNode : public rclcpp_lifecycle::LifecycleNode
{
    // اسٹیٹس: غیر ترتیب، غیر فعال، فعال، حتمی
    CallbackReturn on_configure(const rclcpp_lifecycle::State & state);
    CallbackReturn on_activate(const rclcpp_lifecycle::State & state);
    CallbackReturn on_deactivate(const rclcpp_lifecycle::State & state);
    CallbackReturn on_cleanup(const rclcpp_lifecycle::State & state);
    CallbackReturn on_shutdown(const rclcpp_lifecycle::State & state);
};
```

### ٹائم مینجمنٹ

ROS2 متعدد وقت ڈومینز فراہم کرتا ہے:

**سسٹم ٹائم:** آپریٹنگ سسٹم سے وال-کلاک ٹائم
**سیمیولیشن ٹائم:** سیمیولیشن ماحول سے وقت
**سٹیڈی ٹائم:** میزورمنٹس کے لیے مونوٹونک ٹائم

```cpp
// ٹائم سورس انتخاب
auto time_source = std::make_shared<rclcpp::TimeSource>(node);
time_source->attachClock(node->get_clock());  // سسٹم ٹائم
time_source->attachClock(sim_clock);          // سیمیولیشن ٹائم
```

### ایونٹ ہینڈلنگ

ROS2 ایونٹ-بیسڈ پروگرامنگ فراہم کرتا ہے:

```cpp
// ایونٹ کال بیک
auto event_handler = node->get_graph_event();
while(rclcpp::ok()) {
    node->wait_for_graph_change(event_handler, 1s);
```

## ROS2 ایکو سسٹم انٹیگریشن

### مڈل ویئر موازنہ

 مختلف DDS ایمپلیمنٹیشنز مختلف تنازعات پیش کرتے ہیں:

**Fast DDS:** زیادہ کارکردگی، اوپن سورس، ROS2 میں ڈیفالٹ
**Cyclone DDS:** ہلکا پھلکا، وسائل کی کارآمدی
**RTI Connext:** کمرشل، ادارے کی خصوصیات

### ہارڈ ویئر انٹیگریشن

ROS2 ہارڈ ویئر ایبسٹریکشن کو مندرجہ ذیل کے ذریعے فراہم کرتا ہے:

**ROS2 کنٹرول:**
- جوائنٹ اسٹیٹ انٹرفیسز
- پوزیشن/رفتار/ایفروٹ کنٹرول
- ہارڈ ویئر ایبسٹریکشن لیئر (HAL)

**ہارڈ ویئر ایبسٹریکشن پیکیج (HAP):**
- معیاری انٹرفیسز
- سینسر اور ایکٹو ایٹر ایبسٹریکشن
- وسائل کا نظم

## ڈی پلائمنٹ کے خیالات

### کراس-کمپائلیشن

ROS2 ایمبیڈیڈ سسٹم کے لیے کراس-کمپائلیشن کی حمایت کرتا ہے:


### وسائل کی پابندیاں

وسیلے-محدود سسٹم کے لیے:
- کم سے کم ROS2 ڈسٹری بیوشنز
- میموری استعمال کے لیے اسٹیٹک تجزیہ
- کوڈ سائز کی بہتری

### ڈی پلائمنٹ حکمت عمل

**AOT کمپائلیشن:**
- کارکردگی کے لیے ایڈاونس آف ٹائم کمپائلیشن
- کم رن ٹائم اوور ہیڈ
- مخصوص ہارڈ ویئر کے لیے مطابقت

**کنٹینرائزیشن:**
- ڈی پلائمنٹ کے لیے ڈوکر کنٹینرز
- الگ ماحول
- مطابقت والے انحصار مینجمنٹ

## معیارات اور تابعیت

### محفوظی کے معیارات

ROS2 محفوظی- critical ایپلی کیشنز میں استعمال کیا جا سکتا ہے:

**IEC 61508:** برقی سسٹم کے لیے فنکشنل محفوظی
**ISO 26262:** آٹوموٹو ایپلی کیشنز کے لیے فنکشنل محفوظی
**DO-178C:** ایئربورن سسٹم میں سافٹ ویئر کے خیالات

### ریل ٹائم معیارات

**POSIX ریل ٹائم ایکسٹینشنز:** معیاری ریل ٹائم APIs
**OMG DDS:** صنعتی معیار ڈیٹا ڈسٹری بیوشن
**ROS-Industrial:** مینوفیکچرنگ-خصوصی توسیعات

### ابھرتے ہوئے ٹیکنالوجیز

**ایج کمپیوٹنگ انٹیگریشن:**
- وسائل سے محروم آلات کے لیے بہتر بنایا گیا
- کلاؤڈ-سے-ایج ڈی پلائمنٹ پیٹرنز
- تقسیم شدہ کمپیوٹنگ ماڈلز

**AI/ML انٹیگریشن:**
- TensorFlow/PyTorch انٹیگریشن
- GPU ایکسلریشن سپورٹ
- ماڈل ڈی پلائمنٹ ٹولز

## کلیدی نکات

- ROS2 ROS1 کے مقابلے میں بہتر سیکیورٹی اور ریل ٹائم صلاحیتیں فراہم کرتا ہے
- DDS-بیسڈ کمیونیکیشن قابل شناخت QoS کنٹرولس ممکن بناتا ہے
- کمپوننٹ آرکیٹیکچر کارکردگی کی بہتری کی اجازت دیتا ہے
- جامع ٹیسٹنگ اور سیمیولیشن ٹولز دستیاب ہیں
- ہارڈ ویئر ایبسٹریکشن کے ساتھ وسیع ایکو سسٹم
- محفوظی- critical ایپلی کیشن سپورٹ

## جائزہ سوالات

1. کمیونیکیشن کے لحاظ سے ROS1 اور ROS2 کے درمیان فرق کی وضاحت کریں۔
2. کوالٹی آف سروس (QoS) پالیسیز ROS2 کمیونیکیشن کو کیسے متاثر کرتی ہیں؟
3. لائف سائیکل نوڈ تصور اور اس کے استعمال کے معاملات کی وضاحت کریں۔
4. ROS2 میں DDS کمیونیکیشن ماڈل کی کلیدی خصوصیات کیا ہیں؟
5. ROS2 ریل ٹائم پروگرامنگ اور میموری الاؤکیشن کو کیسے ہینڈل کرتا ہے؟

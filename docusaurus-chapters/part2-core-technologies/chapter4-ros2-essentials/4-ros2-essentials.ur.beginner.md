# ROS2 ا Essentials (اردو بیگنر ورژن)

## باب کا جائزہ

ROS2 (روبوٹ آپریٹنگ سسٹم 2) اصل میں ایک آپریٹنگ سسٹم نہیں ہے، بلکہ یہ ایک مڈل ویئر فریم ورک ہے جو روبوٹ سافٹ ویئر تیار کرنے کے لیے لائبریریز، ٹولز، اور رسمی طور پر قواعد فراہم کرتا ہے۔ یہ روبوٹکس ڈویلپمنٹ کے لیے معیاری فریم ورک ہے، جو مختلف پلیٹ فارمز پر روبوٹ سافٹ ویئر کا اشتراک، دوبارہ استعمال، اور برقرار رکھنا آسان بنا دیتا ہے۔

### ROS2 کیا ہے؟

ROS2 روبوٹ آپریٹنگ سسٹم کی دوسری نسل ہے۔ یہ سافٹ ویئر لائبریریز، ٹولز، اور قواعد کا ایک مجموعہ ہے جو ڈویلپرز کو روبوٹ ایپلی کیشنز تیار کرنے میں مدد فراہم کرتا ہے۔ اسے ایک سیٹ کے طور پر سمجھیں جس کے بلڈنگ بلاکس آپ کو روبوٹکس کے مسائل کو حل کرنے پر توجہ مرکز کرنے دیتے ہیں بجائے کم لیول کے مواصلات اور ہارڈ ویئر انٹرفیس کو ہینڈل کرنے کے۔

**کلیدی خصوصیات:**
- **ہارڈ ویئر ابسٹریکشن**: مختلف ہارڈ ویئر اجزاء کی پیچیدگی کو چھپاتا ہے
- **ڈیوائس ڈرائیورز**: سینسرز اور ایکٹو ایٹرز کے لیے معیاری انٹرفیسز فراہم کرتا ہے
- **کمیونیکیشن انفراسٹرکچر**: روبوٹ کے مختلف حصوں کے درمیان کمیونیکیشن کو فعال کرتا ہے
- **پیکیج مینجمنٹ**: کوڈ کو قابل استعمال پیکیجز میں منظم کرتا ہے
- **معیاری ٹیسٹنگ ٹولز**: کوڈ کی کوالٹی اور قابل اعتمادی کو یقینی بنانے میں مدد کرتا ہے

## بنیادی تصورات

### نوڈس

ROS2 میں، ایک نوڈ ایک عمل ہے جو کمپیوٹیشن کرتا ہے۔ نوڈس ROS2 ایپلی کیشن کے بنیادی بلڈنگ بلاکس ہیں۔ ہر نوڈ عام طور پر ایک واحد کام یا فنکشن کی ذمہ داری لیتا ہے۔

**مثالی نوڈس:**
- ایک نوڈ جو کیمرے سے ڈیٹا پڑھتا ہے
- ایک نوڈ جو سینسر ڈیٹا کی پروسیسنگ کرتا ہے
- ایک نوڈ جو موٹر کو کنٹرول کرتا ہے
- ایک نوڈ جو روبوٹ پاتھس کو منصوبہ بند کرتا ہے

### ٹاپکس اور میسیجز

ٹاپکس کمیونیکیشن چینلز ہیں جو نوڈس کو ڈیٹا کا تبادلہ کرنے کی اجازت دیتے ہیں۔ نوڈس ٹاپکس پر میسیجز شائع کر سکتے ہیں یا ٹاپکس کو سبسکرائب کر سکتے ہیں تاکہ میسیجز وصول کر سکیں۔

**ٹاپکس کیسے کام کرتے ہیں:**
1. ایک نوڈ ٹاپک پر ڈیٹا شائع کرتا ہے (مثلاً سینسر ریڈنگز)
2. کوئی بھی تعداد میں نوڈس اس ٹاپک کو سبسکرائب کر سکتے ہیں
3. تمام سبسکرائبرز ایک ہی ڈیٹا وصول کرتے ہیں
4. کمیونیکیشن غیر مترتبت اور ڈیکوپلڈ ہے

### سروسز

سروسز ریکوئسٹ-ریسپانس کمیونیکیشن پیٹرن فراہم کرتے ہیں۔ ایک نوڈ ایک سروس فراہم کرتا ہے، اور دیگر نوڈس سروس کے انجام پانے کی درخواست کر سکتے ہیں۔

**سروس کی مثال:**
- ایک "میپ محفوظ کرنا" سروس جہاں ایک نوڈ دوسرے نوڈ کو موجودہ میپ کو محفوظ کرنے کی درخواست کر سکتا ہے
- ایک "پاتھ پلاننگ" سروس جہاں ایک نوڈ منزل تک ایک راستہ کی درخواست کر سکتا ہے

### ایکشنز

ایکشنز سروسز کی طرح ہیں لیکن طویل وقت تک جاری رہنے والے کاموں کے لیے۔ وہ انجام دینے کے دوران فیڈ بیک فراہم کرتے ہیں اور منسوخ کیے جا سکتے ہیں۔

**ایکشن کی مثال:**
- ایک مخصوص مقام پر روبوٹ کو منتقل کرنا (جس میں وقت لگ سکتا ہے)
- ایک جامع مینوپولیشن کام انجام دینا

## اپنا ROS2 ماحول سیٹ کرنا

### انسٹالیشن

ROS2 کو Ubuntu، Windows، یا macOS پر انسٹال کیا جا سکتا ہے۔ سب سے عام انسٹالیشن Ubuntu Linux پر ہے۔

**تجویز کردہ سسٹم کی ضروریات:**
- Ubuntu 22.04 LTS (Jammy Jellyfish) یا نئی
- 8GB RAM یا زیادہ
- کم از کم 10GB مفت ڈسک سپیس

### ROS2 ڈسٹری بیوشنز

ROS2 ریلیز "ڈسٹری بیوشنز" کہلاتے ہیں اور حروف تہجی کے لحاظ سے نامزد کیے جاتے ہیں۔ موجودہ تجویز کردہ ڈسٹری بیوشن **Humble Hawksbill** (ROS2 Humble) ہے، جو ایک LTS (Long-Term Support) ورژن ہے۔

### ورک سپیس سیٹ اپ

ROS2 اپنے منصوبوں کو منظم کرنے کے لیے ایک ورک سپیس کا استعمال کرتا ہے۔ ایک ورک سپیس صرف ایک ڈائریکٹری ہے جہاں آپ اپنے ROS2 پیکیجز کو تخلیق اور تعمیر کریں گے۔

**بنیادی ورک سپیس سٹرکچر:**
```
my_workspace/
├── src/          # سورس کوڈ یہاں جاتا ہے
├── build/        # بلڈ فائلز (خودکار طور پر تیار ہوتی ہیں)
├── install/      # انسٹال فائلز (خودکار طور پر تیار ہوتی ہیں)
└── log/          # لاگ فائلز (خودکار طور پر تیار ہوتی ہیں)
```

## اپنا پہلا ROS2 پیکیج تخلیق کرنا

ایک پیکیج ROS2 میں بنیادی تعمیر کا یونٹ ہے۔ یہ سورس کوڈ، کنفیگریشن فائلز، اور دیگر وسائل پر مشتمل ہے۔

### پیکیج سٹرکچر

```
my_package/
├── CMakeLists.txt    # C++ پیکیجز کے لیے بلڈ کنفیگریشن
├── package.xml       # پیکیج میٹا ڈیٹا اور انحصار
├── src/              # C++ سورس فائلز
├── include/          # C++ ہیڈر فائلز
├── launch/           # متعدد نوڈس شروع کرنے کے لیے لانچ فائلز
├── config/           # کنفیگریشن فائلز
└── test/             # ٹیسٹ فائلز
```

### ایک پیکیج تخلیق کرنا

آپ `ros2 pkg create` کمانڈ کا استعمال کرکے ایک نیا پیکیج تخلیق کر سکتے ہیں:

```bash
cd ~/my_workspace/src
ros2 pkg create --build-type ament_cmake my_first_package
```

## ROS2 چلانا

### ROS2 ڈیمن شروع کرنا

ROS2 کے ساتھ کام کرنے سے پہلے، آپ کو ROS2 ڈیمن شروع کرنے کی ضرورت ہے:

```bash
source /opt/ros/humble/setup.bash
```

یہ اکثر آپ کی `.bashrc` فائل میں شامل کرنا عام بات ہے تاکہ یہ خود بخود چلے:

```bash
echo "source /opt/ros/humble/setup.bash" >> ~/.bashrc
```

### اپنی ورک سپیس کو تعمیر کرنا

پیکیجز تخلیق کرنے کے بعد، آپ کو اپنی ورک سپیس کو تعمیر کرنے کی ضرورت ہے:

```bash
cd ~/my_workspace
colcon build
source install/setup.bash
```

### عام ROS2 کمانڈز

**فعال نوڈس کی فہرست:**
```bash
ros2 node list
```

**ایک مخصوص نوڈ کے بارے میں معلومات حاصل کریں:**
```bash
ros2 node info <node_name>
```

**ٹاپکس کی فہرست:**
```bash
ros2 topic list
```

**ٹاپک سے میسیجز ایکو کریں:**
```bash
ros2 topic echo <topic_name>
```

**ٹاپک پر ایک میسیج شائع کریں:**
```bash
ros2 topic pub <topic_name> <msg_type> <args>
```

## بنیادی ROS2 ٹولز

### rviz2

rviz2 ایک 3D وژولائزیشن ٹول ہے جو آپ کو 3D ماحول میں روبوٹ ڈیٹا کو دیکھنے کی اجازت دیتا ہے۔ آپ دیکھ سکتے ہیں:
- روبوٹ ماڈلز
- سینسر ڈیٹا (لیزر سکینز، پوائنٹ کلاؤڈز)
- میپس
- پاتھس
- کوآرڈینیٹ فریمز

### rqt

rqt ایک GUI فریم ورک ہے جو مختلف وژولائزیشن اور ڈیبگنگ ٹولز فراہم کرتا ہے۔ عام پلگ انز میں شامل ہیں:
- rqt_graph: نوڈ اور ٹاپک کنیکشنز دکھاتا ہے
- rqt_plot: عددی ڈیٹا کو پلاٹ کرتا ہے
- rqt_console: لاگ میسیجز دکھاتا ہے

### ros2 bag

ros2 bag ٹیسٹنگ اور ڈیبگنگ کے لیے ROS2 ڈیٹا کو ریکارڈ اور دوبارہ چلانے کے لیے استعمال کیا جاتا ہے۔

**ڈیٹا ریکارڈ کرنا:**
```bash
ros2 bag record /topic1 /topic2 -o my_recording
```

**ڈیٹا دوبارہ چلانا:**
```bash
ros2 bag play my_recording
```

## لانچ فائلز

لانچ فائلز آپ کو ایک کمانڈ کے ساتھ متعدد نوڈس شروع کرنے کی اجازت دیتی ہیں۔ یہ جامع روبوٹ سسٹم شروع کرنے کے لیے مفید ہے۔

**مثال لانچ فائل (Python):**
```python
from launch import LaunchDescription
from launch_ros.actions import Node

def generate_launch_description():
    return LaunchDescription([
        Node(
            package='turtlesim',
            executable='turtlesim_node',
            name='sim'
        ),
        Node(
            package='turtlesim',
            executable='turtle_teleop_key',
            name='teleop'
        )
    ])
```

## پیرامیٹر مینجمنٹ

ROS2 پیکیجز کو کنفیگر کرنے کے لیے پیرامیٹرز استعمال کرتا ہے۔ پیرامیٹرز کو رن ٹائم پر سیٹ کیا جا سکتا ہے اور لچک فراہم کرتا ہے۔

**پیرامیٹرز سیٹ کرنا:**
```bash
ros2 run my_package my_node --param param_name:=value
```

**پیرامیٹرز کی فہرست:**
```bash
ros2 param list
```

## کوالٹی آف سروس (QoS)

QoS ترتیبات آپ کو یہ کنفیگر کرنے کی اجازت دیتی ہیں کہ میسیجز کو کیسے ہینڈل کیا جاتا ہے، خاص طور پر ریل ٹائم یا محفوظی کے اہم ایپلی کیشنز میں اہم ہے۔

**عام QoS پروفائلز:**
- **Reliable**: میسیجز کی ترسیل کی ضمانت دی جاتی ہے
- **Best effort**: میسیجز بھیجے جاتے ہیں لیکن ضمانت نہیں ہے
- **Keep last**: سب سے حالیہ N میسیجز رکھیں
- **Keep all**: تمام میسیجز رکھیں

## کمیونیکیشن پیٹرنز

### پبلشر/سبسکرائب پیٹرن

یہ ROS2 میں سب سے عام پیٹرن ہے۔ پبلشرز ٹاپکس پر میسیجز بھیجتے ہیں، اور سبسکرائبرز ٹاپکس سے میسیجز وصول کرتے ہیں۔

**خصوصیات:**
- بہت سے سے بہت کے کمیونیکیشن
- غیر مترتبت
- وقت اور جگہ میں ڈیکوپلڈ

### کلائنٹ/سرور پیٹرن

یہ پیٹرن ریکوئسٹ-ریسپانس کمیونیکیشن کے لیے سروسز کا استعمال کرتا ہے۔

**خصوصیات:**
- ایک سے ایک کمیونیکیشن
- مترتبت
- ریکوئسٹ-ریسپانس ماڈل

### ایکشن کلائنٹ/سرور پیٹرن

فیڈ بیک کے ساتھ طویل وقت تک جاری رہنے والے کاموں کے لیے استعمال ہوتا ہے۔

**خصوصیات:**
- ایک سے ایک کمیونیکیشن
- وسطی فیڈ بیک فراہم کرتا ہے
- منسوخی کی حمایت کرتا ہے

## ROS2 ایکو سسٹم

### مقبول پیکیجز

کچھ عام طور پر استعمال کیے جانے والے ROS2 پیکیجز میں ہیں:
- **navigation2**: روبوٹ نیویگیشن اور راستہ منصوبہ بندی کے لیے
- **moveit2**: روبوٹک مینوپولیشن کی منصوبہ بندی کے لیے
- **turtlebot3**: TurtleBot3 روبوٹس کے ساتھ کام کرنے کے لیے
- **gazebo**: روبوٹ کی شبیہہ کاری کے لیے

### شبیہہ کاری کے ماحول

ROS2 شبیہہ کاری کے ماحول کے ساتھ اچھی طرح کام کرتا ہے:
- **Gazebo**: فزکس-بیسڈ شبیہہ کاری
- **Webots**: جنرل-پرپز روبوٹ سیمیولیٹر
- **Isaac Sim**: NVIDIA کا سیمیولیشن پلیٹ فارم

## بہترین طریقے

### کوڈ کی تنظیم

- معنی خیز پیکیج ناموں کا استعمال کریں
- ROS2 کے نامزد کنونشن کو فالو کریں
- نوڈس کو واحد ذمہ داریوں پر مرکوز رکھیں
- اپنے کوڈ اور پیکیجز کو دستاویز کریں

### ٹیسٹنگ

- اپنے نوڈس کے لیے یونٹ ٹیسٹ لکھیں
- ROS2 کے ٹیسٹنگ فریم ورک کا استعمال کریں
- حقیقی ہارڈ ویئر سے پہلے شبیہہ کاری کے ساتھ ٹیسٹ کریں
- لائنٹرز اور اسٹیٹک تجزیہ ٹولز استعمال کریں

### کارکردگی

- میسیج کی فریکوئنسی کا خیال رکھیں
- ڈیٹا پروسیسنگ کو بہتر بنائیں
- مناسب QoS ترتیبات استعمال کریں
- نوڈ کی کارکردگی کو مانیٹر کریں

## عام مسائل کو حل کرنا

### نیٹ ورک کنفیگریشن

ROS2 کھوج کے لیے ملٹی کاسٹ استعمال کرتا ہے، تو اس بات کو یقینی بنائیں کہ آپ کا نیٹ ورک اس کی حمایت کرتا ہے۔

### ڈیبگنگ ٹولز

عام کنفیگریشن کے مسائل کو تشخیص کرنے کے لیے `ros2 doctor` استعمال کریں۔

### میموری مینجمنٹ

طویل وقت تک چلنے والے نوڈس میں میموری کے استعمال کو مانیٹر کریں۔

## سیکیورٹی کے تحفظات

ROS2 حساس ایپلی کیشنز کے لیے سیکیورٹی کی خصوصیات شامل کرتا ہے:
- **تصدیق**: نوڈ کی اہمیت کی تصدیق کریں
- **اختیارات**: ٹاپکس اور سروسز تک رسائی کو کنٹرول کریں
- **خفیہ کاری**: میسیج مشمولات کی حفاظت کریں

## کلیدی نکات

- ROS2 ایک مڈل ویئر فریم ورک ہے، ایک آپریٹنگ سسٹم نہیں
- یہ روبوٹ کمپوننٹس کے درمیان کمیونیکیشن کے لیے ٹولز فراہم کرتا ہے
- بنیادی تصورات میں نوڈس، ٹاپکس، سروسز، اور ایکشنز شامل ہیں
- جامع سسٹم شروع کرنے کے لیے لانچ فائلز استعمال کریں
- قابل برقرار رکھنے والے کوڈ کے لیے بہترین طریقے کو فالو کریں

## جائزہ سوالات

1. ROS2 اور روایتی آپریٹنگ سسٹم کے درمیان بنیادی فرق کیا ہے؟
2. ROS2 میں پبلشر-سبسکرائب کمیونیکیشن پیٹرن کی وضاحت کریں۔
3. لانچ فائلز کے استعمال کے کیا فوائد ہیں؟
4. ROS2 میں سروسز ٹاپکس سے کیسے مختلف ہیں؟
5. کوالٹی آف سروس (QoS) ترتیبات کے لیے کیا استعمال ہوتا ہے؟
